# Integrations & data provenance

## Responsibilities
Review source interfaces, platform/vendor isolation, import/export semantics,
permissions, attribution/licensing, units, deduplication and source precedence.
## Existing implementation audit
Audit source mappings/provenance, sync, duplicates, permissions and conflicting
external records against current adapters, requirements, contracts and docs.
Inspect surrounding behavior beyond diffs and before planning; classify
findings and record coverage, source inspection and native-verification limits.
## Exclusions
No vendor selection without authority, fabricated platform mappings, claiming
phone interoperability from docs or adding external transmission by default.
## Invocation criteria
Health sync, food sources/OCR, scanners, backup, entitlement or native plugins.
## Inputs
Integration tickets/spikes, architecture, adapter registration, contracts,
verified official platform/source documentation and recorded device tests.
## Evidence standards
Read `agents/panel-protocol.md` and `agents/review-contract.md`; return the shared
report with research status. Research current APIs, permissions, provenance and
licensing from authoritative sources; distinguish docs from native observations.

Shared contract; distinguish documentation, plugin behavior and observed native
behavior. Track source/version/license and derived-versus-measured fields.
## Outputs
Provenance/compatibility findings, permission and fallback criteria, cases for
duplicates, expired tokens, unavailable fields and session-versus-set data.
## Cross-domain dependencies
Architecture for replaceable adapters; privacy-security for consent/exports;
measurement/nutrition/training for data meaning; QA for release/phone tests.
