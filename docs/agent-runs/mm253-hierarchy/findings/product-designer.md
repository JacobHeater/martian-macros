## Findings

Severity is impact-based; confidence says why. "Render" means I saw it in a supplied PNG; "source" means read.

**PD-1 · run evidence · documentation gap · medium · high.** The twelve renders are one viewport each: the app frame is `height: 100%` with a scrolling body (`app.css` 1-14, 32-36), so a 2,600 px page still lays the app out at about 915 px and the rest is grey. Expected per the brief: the first 2,600 px of each destination. Observed: the first 915. Impact: "Nothing lost: every figure reachable within one tap" cannot be judged from the renders for Dashboard, Coach, Progress, Food (below the second group) or Settings (below Profile); my below-fold statements are source-only. **Proposed outcome:** chair action, not a ticket: render the stories with the body unclipped (a tall frame or the body's `overflow` released in the capture) for the "after" set, and keep one true 412 by 915 capture per destination because that is the rule-7 artefact.

**PD-2 · design system / direction · documentation gap (rule conflict) · high · high.** Rule 6 makes every non-primary action a text action; `MmButton` text is Ember (`ui.css` 39-43); anti-cruft §3 allows one Ember element per screen. Source today: Coach shows "History", "See why", "Change", "Answer again" and "Dismiss"/"Skip" as Ember text on one screen; Dashboard shows "Add food" plus three "… details" text buttons. MM-258's "Repeat" as a text action beside the Ember "Start workout" puts two Ember elements in the first 120 px. Impact: the emphasis ladder's top rung is spent on secondary actions, so the one primary no longer reads as the one. **Proposed outcome:** owner decision, before the rebuild: (a) text actions become `--text` at weight 600 (the `heading`/`label` rung) and Ember text is reserved for a screen whose primary is not a fill (the Dashboard bar), or (b) the budget is rewritten to "one Ember fill plus Ember text actions". I recommend (a); it is one rule in `ui.css` and the register's States story shows it. Acceptance: a screen story has at most one `.mm-button-primary`/`.mm-fab` and, under (a), no `.mm-button-text` in Ember.
